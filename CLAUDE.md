# CLAUDE.md — ubx-schema-aws

## What this is

The real, published schema snapshot for the AWS provider — a frozen,
versioned `manifest.json` + `members/*.json` group, generated by
`ubx-provider-dynamic --generate-snapshot-group`, committed here (not
release-only) so a reviewer sees the real diff. A `[providers.aws]` pin in
`ubx` resolves against this repo's own real GitHub Releases via
`provider.AcquireSchema`. Coordinating repo: `github.com/ubiquex/ubiquex`.

**The only real MIXED-SOURCE group in this org** — 430 members spanning two
different schema sources, not one: 1 real CloudFormation resource member
(`aws`, the whole CloudFormation registry in one zip fetch) plus 429 real
Smithy data-source members (`aws_data_<service>`, one per real AWS service
model). Served by `ubx-provider-dynamic`'s own `internal/mixedserver`, the
one piece of code that had to change to serve a mixed group — each source's
own `Generate<Source>Member` was unchanged by mixing.

## Git rules (strict)

- PR-only. Never self-merge — push a branch, open a PR, wait for the founder.
- Before pushing more commits to a branch with an open PR, confirm it is
  STILL open (`gh pr list --state open` or `gh pr view <n>`) — a merged PR's
  branch looks identical to any other from `git status` alone, and a push
  after merge lands nowhere near `main`, silently.
- NO AI attribution anywhere in commits or PR bodies.

## Repo-specific mechanics

- `.github/workflows/hash-watch.yml` — weekly cron + manual dispatch. Builds
  `ubx-provider-dynamic` from ITS OWN real, latest published release tag (not
  `main` HEAD — an untagged build stamps every regenerated snapshot with the
  meaningless `min_binary_version: "dev"`, UBI-194). Never auto-merges. With
  430 members, expect a real regeneration to touch many `members/*.json`
  files — only real, changed members are ever touched.
- `.github/workflows/publish.yml` — manual dispatch only, refuses to
  republish an existing tag. Verify a real release via `gh api
  repos/Ubiquex/ubx-schema-aws/releases/tags/v<version>` after dispatch, not
  the workflow's own exit status.
- **A snapshot's own `schema_format` alone cannot distinguish a real content
  change here** — this repo's own real pre-#24/post-#24 mixed-source-fix
  history is the reason `min_binary_version` exists at all (stamped at
  generation time, not derived from `schema_format`; see `ubx-provider-dynamic`'s
  own `CLAUDE.md`/`HISTORY.md`).
